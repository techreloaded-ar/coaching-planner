# US-016: Vista avanzamento offerte con residuo giornate — Piano di Implementazione

**Generato da:** Team di Pianificazione ARchetipo
**Data:** 2026-07-03

---

## Spec

**Epic:** EP-004 — Reportistica
**Priorità:** HIGH | **Punti:** 3

**Storia Utente**
Come Stefano, amministratore, voglio una vista di avanzamento per offerta con le giornate erogate rispetto a quelle previste e il residuo, così da accorgermi per tempo quando un'offerta si avvicina all'esaurimento dei giorni venduti.

**Criteri di Accettazione**
- Per ogni offerta sono mostrate giornate previste, giornate erogate (1 giornata = 8 ore) e residuo
- Le giornate erogate sono dettagliate per collaboratore
- Un residuo negativo o esaurito è evidenziato visivamente
- La vista riflette sempre i dati correnti delle attività registrate

---

## Soluzione Tecnica

La vista riusa lo stesso schema a tre livelli del report "Importi da fatturare per cliente" (US-015): funzione di dominio pura → livello dati serializzabile in `src/lib/report.ts` → pagina RSC + Client Component nell'area Back Office. La differenza sostanziale è che l'avanzamento è **cumulativo sull'intero ciclo di vita dell'offerta** (non mensile): aggrega tutte le righe attività di ogni offerta senza filtro sul mese, perché il residuo dei giorni venduti si consuma nel tempo. Nessuna navigazione mensile.

- **Dominio (funzione pura):** nuova `calcolaAvanzamentoOfferte(offerte, righe)` in `src/domain/consuntivi/index.ts`, senza dipendenze da Prisma/framework. Per ogni offerta calcola giornate previste (`giorniPrevisti`), giornate erogate (`somma ore fatturabili / ORE_PER_GIORNATA`), residuo (`previste - erogate`), percentuale di utilizzo e stato, con il dettaglio delle giornate erogate per collaboratore.
- **Ordinamento per criticità:** le offerte sono ordinate per percentuale di utilizzo decrescente, così quelle prossime all'esaurimento o oltre budget compaiono per prime (a parità, per codice offerta).
- **Stato dell'offerta (evidenza visiva):** `OLTRE_BUDGET` se residuo < 0, `ESAURITA` se residuo = 0, `IN_ALLERTA` se utilizzo ≥ 85% con residuo ancora positivo, altrimenti `IN_CORSO`. Soglia di allerta centralizzata come costante `SOGLIA_ALLERTA_UTILIZZO = 0.85`.
- **Giornate erogate = solo le ore fatturabili / 8** (decisione del committente): le righe con `fatturabile = false` NON concorrono al consumo dei giorni venduti dell'offerta. Conversione fissa 1 giornata = 8 ore tramite `ORE_PER_GIORNATA`.
- **Livello dati:** nuova `reportAvanzamentoOfferte()` in `src/lib/report.ts` con `richiediRuoloApi("AMMINISTRATORE")`. Legge tutte le offerte (con cliente) e tutte le righe attività di tutti i collaboratori (con collaboratore), senza filtro temporale, e restituisce un risultato interamente serializzabile (Decimal → string, nessun Date grezzo). Il flag `fatturabile` di ogni riga viene passato alla funzione di dominio, che applica il filtro.
- **UI:** nuova rotta `src/app/(back-office)/report/avanzamento-offerte/` (pagina RSC con `richiediRuolo("AMMINISTRATORE")` + Client Component) che replica lo stile del report esistente (schede `rounded-[11px]`, accenti indigo, dark mode) aggiungendo barra di avanzamento, badge di stato, numeri previste/erogate/residuo, tabella dettaglio per collaboratore e scheda totali di portafoglio. Mockup di riferimento in `docs/mockups/US-016/`.
- **Navigazione:** aggiunta di una voce "Avanzamento offerte" nella sidebar del Back Office (`console-sidebar.tsx`), affiancata al report esistente (rinominato per chiarezza in "Fatturazione clienti").

**Casi limite gestiti:** offerta con `giorniPrevisti = 0` (evita divisione per zero: utilizzo 0 se nessuna erogazione, altrimenti oltre budget); offerta senza attività fatturabile (residuo = previste, dettaglio collaboratori vuoto, stato IN_CORSO); nessuna offerta a sistema (stato vuoto coerente con il report fatturazione).

### Decisioni confermate dal committente
- **Giornate erogate = solo righe fatturabili.** Le righe non fatturabili non concorrono al residuo dei giorni venduti.
- **Sono mostrate tutte le offerte** presenti a sistema (comprese quelle senza attività), per dare visione completa della capacità venduta.
- **Soglia di allerta all'85%** dell'utilizzo prima dell'evidenza "quasi esaurita". Valore centralizzato come costante di dominio.

- `ReportAvanzamentoOfferte` (output complessivo): `perOfferta: VoceAvanzamentoOfferta[]`, `totali: { giornatePrevisteTotali, giornateErogateTotali, residuoTotale }`.

Regole di calcolo:
- Considerare ai fini dell'erogato SOLO le righe con `fatturabile = true`; le righe non fatturabili sono ignorate nel conteggio giornate.
- `giornateErogate = somma(ore fatturabili) / ORE_PER_GIORNATA` (aggregando tutte le righe fatturabili dell'offerta).
- `residuo = giornatePreviste - giornateErogate`.
- `percentualeUtilizzo = giornatePreviste > 0 ? (giornateErogate / giornatePreviste) : (giornateErogate > 0 ? 1.01 : 0)` (guardia divisione per zero; un'offerta con 0 giorni previsti ma erogato > 0 è oltre budget).
- Stato: `OLTRE_BUDGET` se `residuo < 0`; `ESAURITA` se `residuo === 0` (e giornatePreviste > 0); `IN_ALLERTA` se `percentualeUtilizzo >= SOGLIA_ALLERTA_UTILIZZO` con `residuo > 0`; altrimenti `IN_CORSO`.
- Costante esportata `SOGLIA_ALLERTA_UTILIZZO = 0.85`.
- Dettaglio `perCollaboratore` aggregato per `collaboratoreId` sulle sole righe fatturabili, ordinato per `giornateErogate` decrescente (a parità per nome); i collaboratori con solo righe non fatturabili non compaiono.
- `perOfferta` include TUTTE le offerte passate in input (anche senza attività fatturabile: erogato 0, residuo = previste). Ordinamento per `percentualeUtilizzo` decrescente, a parità per `offertaCodice`.
- Totali = somma di previste, erogate e residuo su tutte le offerte.
